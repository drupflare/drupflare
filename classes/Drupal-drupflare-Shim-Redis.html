Shim

\Drupal\drupflare\Shim Redis

The phpredis client a module calls, answered from the site's own database.

The phpredis extension is not compiled in and a Worker has no Redis to dial. drupal/redis picks its client by class existence, so this class, aliased as \Redis, is what its phpredis client constructs and what a module's direct \Redis use gets. No socket opens: a key lives in a row of {@see \Drupal\drupflare\Shim\KeyValueRedisStore}, which is part of the database, so a dump, an export and a backup carry it and drangler preview can seed it from the source's Redis.

What it answers for is the string commands a module uses to keep state: get, set with an expiry or NX/XX, the multi-key forms, delete, exists, expiry and its reads, keys and scan, the counters. A hash, list, set or sorted-set command, a script and a transaction are not here. They throw {@see \Drupal\drupflare\Shim\RedisException} and record a degradation rather than answering with data a real Redis would not have produced.

scan()

scan(int|string|null  $iterator, string|null  $pattern = null, int  $count = 0) : array<int,string>|false

Answers one batch holding every match, then sets the iterator to 0.

A caller loops until the iterator is the integer 0, which this reaches on the first call, so a module's do { scan() } while ($it !== 0) runs once. FALSE is what phpredis answers when an iteration is already over.
