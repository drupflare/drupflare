\Drupal\drupflare\Shim KeyValueRedisStore

The Redis stand-in's keys, in the table core already ships for expiring key/value pairs.

key_value_expire is part of every Drupal database, so a dump, an export and a backup carry the keys with nothing else to configure, and a site moved off the edge takes them with it. One collection per Redis database number.

The row name is the key itself, or a digest when the key is longer than the column or is not valid UTF-8; the real key travels inside the value either way, so listing never has to reverse a digest. A value that is not valid UTF-8 is stored base64 encoded, because the bridge to the database carries text.

Core creates the table the first time its own expirable store is used, which a fresh site may not have done, so the first statement that fails makes core create it and runs once more.
